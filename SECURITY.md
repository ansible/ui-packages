# Security Policy

## Reporting a security vulnerability

Email security reports to [security@ansible.com](mailto:security@ansible.com).
Do not report vulnerabilities through public channels such as GitHub issues,
pull requests, the Ansible Forum, or social media.

## What to include

- **Title:** A clear, concise summary.
- **Impacted project:** A link to the affected project or package.
- **Reporter details:** Your name or handle and affiliation, if you want to share them.
- **Vulnerability description:** Technical details of the issue.
- **Affected versions:** Known affected versions.
- **Reproduction steps:** A minimal example that reproduces the issue.
- **Impact assessment:** Potential exploit scenarios and severity.
- **Suggested fix:** A proposed remediation, if available.
- **Disclosure status:** Whether the issue has been shared or published, and any planned disclosure.

## Response

The Ansible Security Team aims to confirm receipt within one business day and
coordinates assessment, remediation, and disclosure according to severity and
impact. See the [Ansible Security Policy](https://ansible.com/security) for the
full process.

## Supported versions

The packages already published by this repository will not receive new
releases. Support and backport policies for future packages will be documented
with their release policy before their first publication.
